## TPC-C总览
**五类事务的比例与读写特征**（基于 Stanford 整理的 TPC-C 工作集数据）

由9张表组成，这些表通过十个外键关系相连

除了Item表之外，所有内容都是根据数据库初始加载期间生成的仓库数量(**W**)按基数缩放的。
即一个仓库(W)有10个地区、3万个客户、30万以上订单

每个订单又分为New-Order和Order-line两部分
- **New-Order**是用来标示订单是否为新订单，在完成订单的发货操作后，New-Order中的记录将被删除
- **Order-line**是订单中进行批发的商品订购流水，每个订单有5到10个交易商品。
**Stock**是用来记录**Warehouse**的库存情况，**Item**是记录Warehouse中所存储的商品。

该模式由5个不同的事务使用，这些事务在表上产生各种不同的访问模式。
- Item为只读。
- **Warehouse**(仓库)，**District**(地区)，**Customer**(客户)和**Stock**(库存)是可读/可写的。
- **New-Order**是插入、读取和删除，就像一个在任何给定时间大约有 W * 9000行的队列。
- **Order**和**Order-Line**接收插入，插入的每一行都有一个时间延迟的更新，之后该行就过时了，将来可能很少被读取。
- **History**(历史)只是插入的。

## 五大事务
## NewOrder
最核心的事务之一
### 主要操作
- 查询客户和仓库的相关信息
- 更新仓库的订单ID
- 插入新订单信息
### 核心SQL语句
```sql
SELECT d_tax, d_next_o_id FROM bmsql_district WHERE d_w_id = ? AND d_id = ? FOR UPDATE;
SELECT c_discount, c_last, c_credit, w_tax FROM bmsql_customer JOIN bmsql_warehouseON (w_id = c_w_id) WHERE c_w_id = ? AND c_d_id = ? AND c_id = ?;

```

## OrderStatus
### 主要操作(纯读事务)
1. 先根据客户 ID（`c_id`）查出客户信息。
2. 去订单表（`bmsql_oorder`）里，找这个客户**最新（`max(o_id)`）**的一笔订单。
3. 去订单明细表（`bmsql_order_line`）里，查出这笔订单买了哪些商品。
### 核心SQL语句
```mysql
SELECT c_first, c_middle, c_last, c_street_1, c_street_2, c_city, c_state, c_zip, c_phone, c_since, c_credit, c_credit_lim, c_discount, c_balance FROM bmsql_customer WHERE c_w_id = ? AND c_d_id = ? AND c_id = ? FOR UPDATE;
SELECT o_id, o_entry_d, o_carrier_id FROM bmsql_oorder WHERE o_w_id = ? AND o_d_id = ? AND o_c_id = ? AND o_id = (SELECT max(o_id) FROMbmsql_oorder WHERE o_w_id = ? AND o_d_id = ? AND o_c_id = ?);
SELECT ol_i_id, ol_supply_w_id, ol_quantity, ol_amount, ol_delivery_d FROM bmsql_order_line WHERE ol_w_id = ? AND ol_d_id = ? AND ol_o_id = ? ORDER BY ol_w_id, ol_d_id, ol_o_id, ol_number;
```

## Delivery

### 主要操作

 1. 在待发货队列（`bmsql_new_order`）里，找出**最早**进入队列的订单。
 2. 更新订单表（`bmsql_oorder`），打上承运商 ID（`o_carrier_id`）。
 3. 去订单表里查出这个订单是谁下的（拿到 `c_id`）。
 4. 更新订单明细表（`bmsql_order_line`），打上发货时间（`ol_delivery_d`）。
 5. 更新客户表（`bmsql_customer`），把客户余额增加（货到付款），并累加发货次数。
- **TPC-C 定位**：**重度读写混合事务**。虽然只占 4%，但它一次要处理 10 个地区的数据。

### 核心SQL语句
```sql
DELETE FROMbmsql_new_order WHERE no_w_id = ? AND no_d_id = ? AND no_o_id = ?;
UPDATE bmsql_oorder SET o_carrier_id = ? WHERE o_w_id = ? AND o_d_id = ? AND o_id = ?;
SELECT o_c_id FROMbmsql_oorder WHERE o_w_id = ? AND o_d_id = ? AND o_id = ?;
UPDATE bmsql_order_line SET ol_delivery_d = ? WHERE ol_w_id = ? AND ol_d_id = ? AND ol_o_id = ?;
UPDATE bmsql_customer SET c_balance = c_balance + ?, c_delivery_cnt = c_delivery_cnt + 1 WHERE c_w_id = ? AND c_d_id = ? AND c_id = ?;
```

## StockLevel

### 主要操作
1. 查当前片区（District）的最新订单号（`d_next_o_id`）。
2. 找出最近 20 笔订单中包含的所有商品 ID（通过 `district` 和 `order_line` 关联）。
3. 去库存表（`bmsql_stock`）里查，在这个仓库里，这些商品中有多少个商品的库存量（`s_quantity`）低于某个阈值。
- **TPC-C 定位**：**纯读事务**。但这是 TPC-C 里**最复杂、最慢的查询**。因为有**join**存在
### 核心SQL语句
```sql
SELECT count(*) AS low_stock FROM
(SELECT s_w_id, s_i_id, s_quantity FROMbmsql_stock WHERE s_w_id = ? AND s_quantity < ? AND s_i_id IN
(SELECT ol_i_id FROMbmsql_districtJOINbmsql_order_lineON ol_w_id = d_w_id AND ol_d_id = d_id AND ol_o_id >= d_next_o_id - 20 AND ol_o_id < d_next_o_id WHERE d_w_id = ? AND d_id = ? )
) AS L;
```

规定**编译产物的输出位置**：
`${CMAKE_BINARY_DIR}` 就是构建目录 `build/`
- `ARCHIVE`：静态库（`.a`）→ 放到 `build/lib/`；
- `LIBRARY`：动态库（`.so`）→ 放到 `build/lib/`；
- `RUNTIME`：可执行文件 → 放到 `build/bin/`。
**说明这是调试用版本，正式版要进行优化，不能用这些参数了**
- `-O0` 下，编译器不做内联、不做循环优化、不做寄存器分配优化，**程序会明显比 `-O3` 慢**。如果用它跑 TPC-C 测吞吐，得到的数字会远低于真实性能，**不能作为优化前后的对比依据**；
- 好处是调试时变量不会被优化掉，单步跟踪、看调用栈、下断点都准确。`-ggdb3` 还会包含宏展开信息
